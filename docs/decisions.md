# Decisions

Newest last. Format: **D#: decision.** Why. Status (`decided` by the owner, `provisional` until the grill confirms it).

- **D1: Books come from user-uploaded EPUBs only.** DRM rules out store books, and the owner chose upload (2026-09-27). A public-domain catalogue is out of scope for now. `decided`
- **D2: One shared file per book.** Both partners read the same uploaded bytes (`book.sha256`), so positions match exactly. This fixes StoryGraph's edition mismatch. `provisional`
- **D3: Positions are a layout-independent `pos` (spine + char offset / spine length), with anchors stored as CFI + text quote.** Page numbers are display-only. `provisional`
- **D4: Four primitives: Position, Mark, Event, Reveal.** All annotation kinds share one `mark` table; timeline, stats and notifications are derived from `event`. `provisional`
- **D5: The spoiler gate and reveal gate are enforced in Postgres RLS, not in the client.** A client bug must not be able to leak content from ahead. `provisional`
- **D6: Stack: Next.js PWA + Supabase (Auth, Postgres, Storage, Realtime) + pnpm + Tailwind/shadcn + vitest, deployed on Vercel.** Matches the house stack; Supabase covers RLS and realtime in one place. `decided` (2026-09-27)
- **D7: Sync reading mode is last.** It only needs presence, so nothing in the schema depends on it. `provisional`
- **D8: Web PWA first; native comes later on the same Supabase backend. Reader engine: foliate-js**, pinned to upstream commit `78914ae` and installed from git (the npm `foliate-js` package is a third-party republish). The P03 spike (`docs/research/reader-spike.md`) measured that `pos` is identical across font sizes and viewports, and that browser spine lengths equal the upload-time lengths for all 15 spine items. epub.js was rejected: by default it parses XHTML as HTML, which shifts 4 of 15 spine lengths and every offset after a `<pre>` by one. It has also had no release since 2022-02 and is 1.8× the size. `decided`
- **D9: The spoiler lock hides a mark's content and its existence.** No 🔒 chip, because a chip's page and kind (😭 on p.200) is itself a spoiler. Marks appear once your progress reaches them. `decided`
- **D10: Partner position and chapter-finished pushes stay visible while they're ahead.** They show pace, not story content, and "Alex is on p.212" encourages reading together. Marks ahead stay fully hidden (D9). Decided autonomously on 2026-09-27; the owner confirmed it for v1. `decided`
- **D11: Work lands as small verified commits on `master`.** The repo has no remote. Each problem runs in its own worktree and is merged after verification. `decided`
- **D12: Sign-in is email + password (Supabase Auth via `@supabase/ssr`) for v1.** It's the simplest for two partners to set up and for the verification harness to drive. OAuth or magic links can be added later without changing the schema. `provisional`
- **D13: Books are created only on the server.** A server action computes `sha256`, `spine_lengths` and the title/author from the uploaded bytes. Clients can't insert `book` rows, because the spoiler gate's `pos` math trusts `spine_lengths`. `decided`
- **D14: Two tables beyond the four primitives: `reading_day` and `goal` (P31).** A streak needs "did this person read on this local day", which `progress` (one row, overwritten) and `event` (milestones only) can't answer without a per-day record. `goal` is couple settings, not a primitive. Both are written only by a trigger or an RPC. `decided`
- **D15: Reveal-style triggers take a per-prompt advisory lock.** Two partners answering at the same moment each missed the other's uncommitted row, and no reveal event was written (0 of 20 measured). `pg_advisory_xact_lock` on the prompt serialises them; a DB test fires both answers at once 10 times, and it fails without the lock. `decided`
- **D16: Push goes DB trigger → pg_net → Next route `/api/push/dispatch` → web-push.** It isn't an Edge Function, because the wording module, types and service-role client already live in the Next app. The trigger applies the spoiler gate in SQL before posting. The shared secret lives in Vault. Delivery to a real device through a push service is unverified locally. `decided`
- **D17: Broadcast/presence channels are private to the couple (RLS on `realtime.messages`); postgres_changes channels stay public because row RLS already filters them.** On a hosted project, turn off "Allow public access" in Realtime settings. `decided`
- **D18: Chapter names come from the book's own TOC, stored as `book.toc` at upload (F3).** The server parses the EPUB3 nav toc, else the NCX, into `[{ spine, label }]`, first entry per spine item. A spine item takes the label at or before it; one before the first entry is front matter and gets no finished prompt, no discussion page and no push, though its `chapter_finished` event is still written. The timeline leaves front matter out of the discussed line, and `day_totals` leaves it out of today's chapters and the chapter goal. Books uploaded earlier have `toc` null and keep `Chapter {spine+1}`: a backfill would need every stored EPUB re-read for a label change. `decided`
- **D19: foliate-js is patched (`patches/foliate-js@0.0.0.patch`) so it never lays out or reads the background of a section document without a body.** Its paginator re-renders on every resize of its container and reads the background one animation frame after `setStyles`. Both can land while a new section's iframe is still parsing (body null: "Cannot destructure property 'style'", "getComputedStyle … not of type 'Element'") or after the reader left the page (document null: "reading 'documentElement'"). The frame callback reads foliate's private current view, so reader.ts can't guard it; the two-line patch covers every path. A skipped layout is safe because a section lays itself out once loaded. `tests/e2e/reader-errors.spec.ts` fails without it. `decided`
- **D20: Opening a book isn't reading.** The first progress row (opening the book) records no reading day. A reading day starts with the first page turned. Before this, two partners merely opening a book started a streak. `decided`
- **D21: Hardening from Supabase advisors.** RLS policies use `(select auth.uid())`, except `mark_select`, where a sub-select next to `mark_insert`'s EXISTS on `mark` makes Postgres report recursion. No public function is executable by `anon` (also set as the default for new functions). `memory_media_ok` has a pinned search_path. `pg_net` lives in `extensions`. Advisors report only the deliberate `mark_select` warning. `decided`
- **D22: A reaction is any emoji, stored as the character itself (`mark.emoji text`), not an enum.** The owner asked for Discord-style reactions with every emoji. Migration `20260927001800` maps the old enum values to their characters (love → ❤️, funny → 😂, emotional → 😭, surprised → 😮, interesting → 🤔, favorite → 🔥, think → 💭), checks that exactly reactions carry one (1–16 chars, not blank), and allows one reaction per person per emoji per passage (unique on book, author, `locator->>'cfi'`, emoji), folding any older duplicates into the oldest and moving their replies onto it. `couple_stats.reactions` is keyed by the emoji. The seven stay as quick picks and the guess game keeps its own four options. The picker is `frimousse` (headless, ~12 kB) with emojibase data fetched from jsdelivr on first open. Chips sit under the passage's quote in the thread and along the bottom of the page for passages on it, since the reader exposes no on-page rect for a passage. `decided`
